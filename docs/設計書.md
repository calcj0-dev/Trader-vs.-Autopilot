## 1. 目的と対象

### 1.1 目的
- 売上ではなく、**話題化と、本命アプリ TAMERU への誘導**
- 遊んだ人に、説教ではなく体験として次の2つを感じてもらう
  1. 売買のタイミングを当て続けるのは難しい
  2. 積立は、タイミングを考えずに済む方法

### 1.2 成功の目安（KPI）
| 種類 | 指標 |
| --- | --- |
| 主KPI | Xでのシェア数、TAMERU へのクリック数、Xのフォロー |
| 副KPI | プレイ数、完走率（開始→結果画面）、リプレイ率 |

数値の目標は公開後に決める（U4）。

### 1.3 対象ユーザー
| 対象 | 来る理由 | 本作で起きてほしいこと |
| --- | --- | --- |
| NISA・積立投資を始めた人 | 「積立で合ってるのかな」を確かめたい | 売買してみて、「積立でよかった」と納得する |
| 「自分ならもっとうまく売買できる」と思っている人 | 挑戦状の題名とローソク足に挑発される | 本気で売買して、たいてい負けて、投稿する |
| 投資に興味がある学生 | ゲームとして気軽に遊べる | 暴落・回復の感覚をつかむ |

### 1.4 ゲームの要点（1分で分かる版）
- ブラウザで遊ぶ。スマホ縦画面が最優先。インストール・ログイン不要
- **毎月10万円を受け取る**。20年分の架空の相場（ローソク足の月足）が流れ（最初の設定は1年4秒＝全体80秒）、「買」「売」の2ボタンで売買する
- 比べる相手の「積立」は、毎月10万円をそのまま買い続ける。20年後に積立を上回れば**勝利**、+10%以上で**圧勝**、+20%以上で**歴史的勝利**。積立と同じ額なら**引き分け**（Q15、2026-10-23 オーナー決定）
- 手数料・税金なし。「買」は手元の現金を全部使う（買い足しも同じボタン）、「売」は全部売る。押した月の終値で約定、1か月に1回まで
- Vite＋TypeScript＋素のDOM＋Canvas。Vercel に静的サイトとして公開。サーバーなし
- 公開時は日本語・円のみ。文言と通貨は分けて持ち、英語・中国語・他の通貨を後で足せる作り

## 3. ゲーム仕様

### 3.1 ゲームの流れ
```
タイトル → ルール説明（「次から表示しない」で省略可）
  → 助走（過去24か月を表示）＋カウントダウン 3・2・1
  → プレイ（240か月＝最初の設定で80秒。毎月10万円を受け取り、買・売・一時停止）
  → 終了の演出（約1秒）→ 結果画面 → もう一回／シェア／TAMERU／フォロー
```

### 3.2 ルールと数値
期間・速さの選択肢は `config.json`、毎月受け取る額は `data/currency/jpy.json` で持つ（Q15、2026-10-23 オーナー決定）。

| 項目 | 値 | 補足 |
| --- | --- | --- |
| 受け取るお金 | **毎月の初めに10万円**（最初の現金は0、株0） | 20年で合計2,400万円（元本） |
| 期間 | 240か月（20年） | 助走の24か月は数えない |
| 速さ | **1年4秒（1か月1/3秒、全体80秒）が最初の設定**（2026-10-26 変更）。設定で1年 4・5・6・8秒 | 一時停止中は止まる |
| 「買」 | 手元の現金を全部使って買う。株を持っていても、受け取った分を買い足せる | 現金があるときだけ押せる（受け取るので、ほぼ毎月押せる） |
| 「売」 | 持っている株を全部売る | 株があるときだけ押せる |
| 約定の値段 | 押した月の終値 | 右端で伸びているローソク足が「今月」 |
| 売買の回数 | 1か月に1回まで | 同じ月の2回目は受け付けない（「買」と「売」を同じ月に両方はできない） |
| 手数料・税金・現金の利息 | なし | 決定事項 #4 のまま |
| 最終評価 | 240か月目の終値で、現金＋株の評価額 | |
| 積立（比較相手） | 毎月受け取った10万円を、その月の終値で全部買う。売らない | 毎月「買」を押すのと同じ |
| 元本（結果で見せる） | 受け取ったお金の合計（m か月目の終わりで (m+1)×10万円） | |

### 3.3 勝敗
最終資産を通貨の最小単位（円なら1円）に四捨五入してから比べる。積立との差は 最終資産÷積立−1（Q15、2026-10-23 オーナー決定）。

| 判定 | 条件 | ID |
| --- | --- | --- |
| 歴史的勝利 | 積立を **+20%以上** 上回る | `historic` |
| 圧勝 | **+10%以上** 上回る | `rout` |
| 勝利 | 積立を上回る | `win` |
| 引き分け | 積立と **同じ額のときだけ**（毎月欠かさず買った場合など） | `draw` |
| 負け | 積立を下回る | `lose` |

- +10%・+20% は `config.json` に置く（身内テストで調整できるように）
- 「一括投資派」「大勝利」「一括放置」はなくした（Q15-2）
- 名前「歴史的勝利」は、ニュース「とにかく何かが歴史的」と同じ言い方（くすっと笑える方向）

### 3.4 状態とボタン
| 状態 | 「買」 | 「売」 |
| --- | --- | --- |
| 現金がある（毎月受け取るので、ほぼいつも） | 押せる（赤）。**株を持っていれば表示は「買増」**（2026-10-26 オーナー決定） | 株があれば押せる（青） |
| 現金がない（今月すでに買った・まだ受け取っていない） | 押せない（灰） | 株があれば押せる |
| 今月はもう注文した | 両方押せない | |
| 一時停止中・カウントダウン中 | 押せない | 押せない |

- 資産の下に、持っているものを両方出す。例：「株 345.6万円（+12.3%）／現金 10万円」
- 増減率は**平均の買値**（買い足しを含む、株を買うのに使った額÷株数）と比べる。チャートの点線も平均の買値
- 押した瞬間：その月のローソク足の下（買）・上（売）に印、ボタンに「注文中…」
- 月が終わったら約定する

## 4. 価格モデルと計算

> 参照実装：相場の作り方は `sim/model.mjs`、資産の計算・勝敗・称号は `sim/monthly.mjs`（Q15 で追加）。**食い違ったら参照実装が正**。TypeScript に移すとき、**乱数を使う順番を変えない**。

### 4.1 全体の流れ
```
相場番号 seed（32bit 符号なし）
  └▶ rng = mulberry32(seed)、normal = Box–Muller(rng)
       ├▶ ① シナリオを選ぶ（rng 1回）
       ├▶ ② シナリオの計画（月ごとの μ・σ・extra と出来事）
       └▶ ③ 264本のローソク足（助走24本＋ゲーム240本）
ゲーム中：毎月10万円を受け取る → 売買 → 月の終値で約定 → 資産の推移
終了時 ：同じ終値の列から積立・元本を計算 → 勝敗 → 称号
```

### 4.2 相場番号と乱数
| 項目 | 決まり |
| --- | --- |
| 相場番号 | 0〜4,294,967,295。プレイごとに `crypto.getRandomValues(new Uint32Array(1))[0]` |
| 画面・URL | 出さない。計測にも送らない |
| 開発用 | 開発ビルドだけ `?seed=` で指定可（`import.meta.env.DEV` のときだけ読む） |
| 相場の乱数 | mulberry32。正規乱数は Box–Muller（2つ作って1つを次に回す） |
| ニュースの乱数 | 相場とは別に `mulberry32(seed ^ 0x5bd1e995)` |
| `Math.random()` | 相場・ニュースには使わない |

### 4.3 シナリオの選び方
`x = rng() × 100`、steady(35)→crash(35)→volatile(22)→decline(8) の順に重みを引き、負になったものを選ぶ。**キーの順番を変えない**。

### 4.4 シナリオの計画
各月に「年率の傾き μ」「年率の揺れ σ」「上乗せ extra（対数）」を決める。助走24か月は全シナリオ共通で μ=5%、σ=15%、extra=0。

| シナリオ | 内容（月は1始まり） |
| --- | --- |
| 右肩上がり | 全期間 μ=6.5%、σ=14%。13か月目以降に調整を平均で年0.35回 |
| 暴落と回復 | 平常 μ=6.5%、σ=14%。**暴落**：開始37〜169か月目、長さ5〜9か月、μ=0・σ=22%、合計約−42%。長さ÷2（切り捨て）の月だけ+8%（だましの反発）。**戻り**：底の翌月から3か月で+22%（σ=20%）。その後18〜36か月で暴落分の9割まで（σ=16%）。暴落の前後（6か月以上離す）に調整を年0.3回 |
| 乱高下 | 上げ（μ=+27%）と下げ（μ=−17%）が交互。各3〜15か月。最初が上げの確率55%。σ=24% |
| 長期下落 | μ=−3%、σ=18%。61〜151か月目のどこかで12か月だけ μ=+15% |

**調整**：前回の終わりから「指数分布（平均 12÷回数 か月）、最短6か月」後に開始。−12〜−22%を1〜3か月で下げ、その95%を2〜6か月で戻す。期間の終わりに収まらないときは入れない。

**乱数を引く順番（参照実装どおり）**
- crash：start → dur → rec → 前半の調整 → 後半の調整 → gloom のずれ
- 調整1回：間隔 → 深さ → down → up
- volatile：最初が上げか → （各区間の長さ）
- decline：rally

### 4.6 ローソク足の作り方（264回）
1. 月の対数リターン `r = (μ − σ²/2)/12 + σ/√12 × z + extra`
2. 月内の20刻み：揺れ `σ/√(12×20)` を20歩足す。i 歩目に `(i/20)×(r − 20歩目の値)` を足して終点を r に合わせる（ブラウン橋）
3. 始値＝前の終値（最初は10,000）、終値＝始値×e^r、高値＝始値×e^(最大)、安値＝始値×e^(最小)

常に 高値 ≧ max(始値, 終値)、安値 ≦ min(始値, 終値)、安値 > 0。
- 終点の補正（ブラウン橋）は小数の誤差で r をわずかに外すことがあり、参照実装では高値が終値をごく小さく下回る（または安値が上回る）ことがある（5,000相場・132万本のうち162本、差は最大 2.2×10⁻¹⁰）。実装では、高値・安値が必ず終値を含むように補正する。乱数の順番は変わらず、参照実装との差は T-02 の許容（1e-9）以内（2026-10-23 M2 で確認）

### 4.7 「今月」のローソク足の伸び（表示のみ）
- 終値 ≧ 始値：始値 → 安値 → 高値 → 終値
- 終値 ＜ 始値：始値 → 高値 → 安値 → 終値
- 各区間は1か月の1/3ずつ、直線で動かす。約定は必ず終値。上部の資産額は表示中の値段で動かしてよい

### 4.8 資産の計算
```
受け取る額 I（10万円）、P(m)＝ゲーム m か月目の終値
プレイヤー（現金 C＝0、株数 S＝0、株に使った額 K＝0 から始める）
  毎月の初め：C += I
  買（m）：S += C ÷ P(m)、K += C、C = 0        … 株を持っていても買い足せる
  売（m）：C += S × P(m)、S = 0、K = 0
  各月末の資産 = C + S × P(m)、最終資産 = 239か月目の資産
  平均の買値 = K ÷ S（株を持っているとき）
積立：毎月「買」を押したのと同じ（受け取った I をその月の終値で全部買う）
元本：m か月目の終わりで (m+1) × I
```
- 計算は小数のまま。比べるときだけ最小単位に丸める
- 参照実装は `sim/monthly.mjs` の `simulatePlayer`・`simulateTsumitate`・`principal`（Q15、2026-10-23 オーナー決定）

### 4.11 期間を変えるとき
- 期間は `config.json` の `gameMonths`、速さは利用者が選ぶ「1年の秒数」（選択肢は `config.json` の `yearSecondsOptions`）。1か月の長さ `monthMs` ＝ 1年の秒数×1000÷12
- 参照実装のシナリオの「何か月目」の指定は240か月前提で、期間を短くすると暴落と回復の相場で配列の外を指して止まる（120か月で約25%の相場が失敗。確認済み）
- そのため、**位置を表す月の指定は240か月に対する割合で持ち、`gameMonths` に合わせて換算する**（Q2、2026-10-23 オーナー決定）。換算は `scaleMonth(m) = Math.round(m × gameMonths / 240)`

| 換算するもの（位置） | 240か月での値（0始まり） |
| --- | --- |
| 暴落の開始 | randInt(36, 168) の両端 |
| 長期下落のだましの戻りの開始 | randInt(60, 150) の両端 |
| 調整を入れ始める月 | 6 |
| 暴落の前後で調整を空ける月数 | 6 |

| 換算しないもの（長さ） | 値 |
| --- | --- |
| 暴落の長さ・戻り・回復の期間 | 5〜9か月・3か月・18〜36か月 |
| 調整の間隔の最短・下げ・戻り | 6か月・1〜3か月・2〜6か月 |
| 乱高下の区間・だましの戻りの長さ | 3〜15か月・12か月 |

- `gameMonths = 240` のとき `scaleMonth(m) = m` なので、数値も乱数の順番も参照実装と完全に同じ（T-02）
- 対象は `gameMonths ≥ 60`。それ未満は `config.json` の読み込み時にエラーにする
- 暴落と回復の相場では、回復が期間内に収まらない場合も配列の外を指さないよう、期間の終わりで打ち切る（240か月では起きないので T-02 に影響しない）

## 6. 構成と技術選定

### 6.1 MVPの構成

### 6.2 技術
| 項目 | 選定 | 理由 |
| --- | --- | --- |
| 言語 | TypeScript（strict） | 計算を間違えにくく |

| 画面 | 素のDOM | 画面4つ・状態少。軽く |
| チャート | Canvas 2D 自作 | 毎コマ描くため |
| 効果音 | Web Audio API 合成 | 素材不要 |
| テスト | Vitest | Vite と同じ設定 |
| 計測 | `@vercel/analytics`（表示）＋ gtag.js（イベント） | オーナー決定 |

### 6.3 置き場所に依存しない作り
| 項目 | 方法 |

### 6.6 データの持ち方（JSON）
**方針：ゲームのデータはコードに書かず、JSON ファイルで持つ。** コード（`.ts`）には処理だけを書く（2026-10-23 オーナー指示）。

| データ | ファイル | 中身 |
| --- | --- | --- |
| ゲームの設定値 | `src/data/config.json` | 期間（月数）・速さの選択肢と最初の設定・勝敗の区切り（+10%・+20%）・助走・表示本数・狭い端末の境目・色・カウントダウンなど演出の時間・ニュースの間隔と表示時間 |
| シナリオ | `src/data/scenarios.json` | 選ぶ順番と割合、各シナリオの μ・σ・暴落の深さ・月の範囲・調整のパラメータ、助走の μ・σ、開始値、月内の刻み数 |
| 称号 | `src/data/titles.json` | 判定順と条件（約定の回数・売った回数・勝敗・積立との差・底値付近・シナリオ）、底値付近の判定（前後の月数・倍率） |
| ニュース | `src/data/news.json` | ランダムのニュースのID一覧、出来事と A〜E の対応、重なったときの順番 |
| 文言 | `src/data/i18n/ja.json` | 画面・ルール・ニュース・称号・種明かし・投稿文・結果画像・免責・プライバシー・TAMERU の紹介文など、画面に出る文字すべて |
| 通貨 | `src/data/currency/jpy.json` | 通貨コード・毎月受け取る額・丸めの単位・表記の形（割る数・小数の桁・前後に付ける文字・3桁区切り） |
| 外部リンク | `src/data/config.json` の `links` | TAMERU（UTM 付き）・X のアカウント・X の投稿画面のURL |

**コードに残すもの**：乱数・相場の作り方の手順・資産の計算・勝敗と称号の判定の仕組み・ニュースの予定表の作り方・画面・描画・計測。数値や文字は JSON から受け取る。

**決まり**
- JSON は Vite でビルド時に取り込む（`import config from './data/config.json'`）。実行時に `fetch` しない（読み込みを速くし、置き場所に依存しないため）
- 型は `.ts` で決め、`data.ts` で `satisfies` を付けて読み込む。項目が足りない・型が違う JSON はビルドでエラーになる（T-19・T-20）
- 環境ごとに変わる値（作品のURL・GA4 の測定ID）は JSON ではなく環境変数（6.3）
- JSON にはコメントを書けないので、各項目の意味は本書（7.6・7.14・10章）に書く
- 公開前に差し替える文言（U2 TAMERU の紹介文・U3 プライバシー・U7 媒体名）は `ja.json` を直すだけで済む
- 参照実装 `sim/model.mjs` は数値をコードに持っているが、`scenarios.json` の値は参照実装とまったく同じにする（T-02・T-20 で確認）。シナリオは名前ごとのまとまり（`"steady": {...}`）で持ち、割合を引く順番（右肩上がり→暴落と回復→乱高下→長期下落）はコード（`core/market.ts` の `SCENARIO_ORDER`）で固定する。順番を変えると同じ相場番号で違う相場になるため、データではなく計算の手順として扱う（2026-10-23 オーナー確認）
- 範囲は `{ "min": 36, "max": 168 }` の形で書く（配列 `[36, 168]` は使わない）。型で「2つの数」を確かめられ、書き間違いをビルドで見つけられるため（2026-10-23 オーナー確認）
- `core/` は DOM・`window`・時刻・`i18n` を参照しない。文字列は ID だけ返す

### 6.7 バージョン管理
**方針**：バージョンは `0.1.0` から始め、**一般公開するときに `1.0.0`** にする。タイトル画面（S1）の右上に表示する（2026-10-23 オーナー指示：バージョン管理）

| 項目 | 決まり |
| --- | --- |

**上げ方**
| 時期 | 上げる桁 | 例 |
| --- | --- | --- |

### 7.7 core/news.ts
```ts
type NewsItem = { atMonth: number; kind: 'random' | 'event'; id: string }; // id 例 'random.07'、'event.A'
function buildNewsSchedule(seed, events, opts: { gameMonths, randomCount, intervalMonths: [min, max], showMonths }): NewsItem[]
```
- 乱数は `mulberry32(seed ^ 0x5bd1e995)`。相場の乱数は使わない
- 予定表はプレイ開始時に**月単位で**作る。`config.json` の秒（間隔6〜10秒・表示4秒）を `monthMs` で月に換算して渡す（Q4、2026-10-23 オーナー決定）。一時停止・端末の速さでは変わらない。速さ（`gameSeconds`）を変えると秒の間隔が保たれ、月数が変わる
- 出来事ニュースの月を決める手順：出来事を月の順に並べる（同じ月なら A→B→C、D・E はその後）→ 前のニュースと同じ月か、A→B→C の順が逆になる場合は、前のニュースの翌月以降の空いている月に送る → ランダムのニュースはその間を埋める（Q1）
- `MarketEvent` の月（相場側の記録）は変えない。送るのはニュースの `atMonth` だけ
- ランダムのニュースのID、出来事と A〜E の対応、重なったときの順番は `news.json` から受け取る。文言は `ja.json`
- 文言の数は「言語ファイルにある数」（`randomCount`）を受け取る

## 8. 時間の進め方と操作

### 8.1 進め方
```
毎コマ（requestAnimationFrame）：
  dt = 今 − 前（最大100msで打ち切り）
  一時停止中でなければ acc += dt
  while (acc ≥ monthMs) { closeMonth(); acc −= monthMs }
  progress = acc ÷ monthMs → 今月のローソク足の伸び（4.7）
  描画
最後の月を締めたら ending（約1秒）→ result
```

### 8.2 一時停止になる場面（自動で再開しない）
⏸／`visibilitychange` で隠れた／`pagehide`／ブラウザの「戻る」／横向き（`matchMedia('(orientation: landscape)')`、スマホのみ）

### 8.3 タッチと画面
| 項目 | 対応 |
| --- | --- |
| 反応 | 「買」「売」は `pointerdown`（`click` は使わない） |
| 拡大の防止 | `touch-action: manipulation`。viewport に `viewport-fit=cover` |
| 長押し | `user-select: none`、`-webkit-touch-callout: none`、`contextmenu` を止める |
| 引っ張って再読み込み | `overscroll-behavior: none`。プレイ画面はスクロールなし |
| 高さ | `100dvh`。`env(safe-area-inset-*)` で切り欠き・ホームバーを避ける |
| 振動 | 約定時 `navigator.vibrate(10)`（対応端末のみ） |
| 音 | 「スタート」を押したときに `AudioContext.resume()` |

### 8.4 性能
- チャートの Canvas は1枚、毎コマ全部描き直す
- 資産額は DOM。値が変わったときだけ書き換える
- 目標：中位の Android で1コマの処理4ms以内、60fps
- 最初に読み込むファイル：合計150KB以下（圧縮後、GA4除く）。Lighthouse モバイル Performance 90以上

| `finish` | 結果画面を開いた | `scenario`、`outcome`（historic／rout／win／draw／lose）、`sells`（0／1-2／3-9／10+）、`speed` |
| `share_click` | Xで投稿／結果画像をシェア・画像を付けてシェア（スマホの共有メニュー）／画像を保存 | `method`（x_intent／web_share／save_image） |
| `main_app_click` | TAMERU・フォロー | `target`（tameru／follow） |
| `retry` | 結果画面の「もう一回」（M1 の「最初から」では送らない） | なし |

- 全イベントに `lang`（ja）・`currency`（JPY）
- `start` の `retry` は、「もう一回」と M1 の「最初から」のどちらで始まっても true。`retry` イベントは「もう一回」だけ（Q8、2026-10-23 オーナー決定）
- **送らないもの**：個人を特定できる情報、相場番号、売買の内容
- 完走率＝finish÷start、リプレイ率＝retry÷finish
- GA4 のカスタムディメンション：scenario、outcome、sells、speed、method、target、chart、retry、lang、currency（登録はオーナー作業）。`lump`・`trades` はなくした（Q15、2026-10-23 オーナー決定）

### 9.3 シェア時のURL
`<VITE_SITE_URL>` だけ（相場番号も計測用の文字も付けない。投稿画面で短く見えるように）（2026-10-26 オーナー決定）

### 9.4 プライバシーについて（M6 の内容・文言は U3）
- **2026-10-26 オーナー決定（U3）**：GA4 を入れていないとき（`VITE_GA_ID` が空）は、Vercel Analytics だけの文言（ページの表示を数える／Cookie を使わない・個人を特定する情報を集めない／ゲームの結果や売買の内容は送らない／端末に保存するのは設定だけ／Vercel のプライバシーポリシーへのリンク）。GA4 を入れたら、下の文言に自動で切り替わる
- アクセス解析に Google Analytics と Vercel Analytics を使っている
- GA は Cookie を使い、匿名で利用状況を集める。個人を特定する情報は集めない
- ゲームの結果（勝敗・売った回数の区分・速さなど）を匿名で記録している
- 端末に保存するのは設定（音・チャート・ルール表示の省略など）だけ
- Google のプライバシーポリシーへのリンク、ブラウザの設定や Google のオプトアウト アドオンで止められること

## 10. 多言語・多通貨

### 10.1 文言（i18n）
| 項目 | 決まり |
| --- | --- |
| 置き場所 | 画面・結果画像・投稿文・ニュース・称号・種明かし・注意書き・ルール・免責・プライバシーの文言は `data/i18n/<言語>.json` だけ（金額の単位の表記は `data/currency/<通貨>.json`） |
| キー | 例 `result.outcome.historic`、`news.random.07`、`news.event.A.source`、`title.from_future`、`scenario.crash.reveal` |
| 型 | `i18n/types.ts` でキーの型を決め、`data.ts` で JSON に `satisfies` を付けて読み込む。キーが足りなければビルドでエラー（T-19） |
| 差し込み | `t('rules.line1', { income, years, seconds })`。文を部品に分けてつながない |
| 選び方 | 起動時に `i18n/index.ts` で1回。公開時は常に `ja`。`<html lang>` も合わせる |

```ts
// i18n/types.ts の形（例）。中身は data/i18n/ja.json に書く
export type Messages = {
  'title.main': string;
  'rules.line1': string;            // '毎月{income}がもらえます。{years}年分の相場が{seconds}秒で流れます'
  'news.random': { source: string; headline: string }[];
  'news.event': Record<'A' | 'B' | 'C' | 'D' | 'E', { source: string; headline: string }>;
  'title': Record<TitleId, string>;
  // …
};
```

### 10.2 通貨
通貨ごとの値は JSON（`data/currency/<通貨>.json`）で持ち、表記を作る処理は `currency/index.ts` に1つだけ書く（Q15、2026-10-23 オーナー決定）。
```json
{
  "code": "JPY",
  "monthlyIncome": 100000,
  "minorUnit": 1,
  "formats": {
    "asset": { "divisor": 10000, "decimals": 1, "prefix": "", "suffix": "万円", "grouping": true },
    "whole": { "divisor": 10000, "decimals": 0, "prefix": "", "suffix": "万円", "grouping": true },
    "plain": { "divisor": 1, "decimals": 0, "prefix": "", "suffix": "円", "grouping": true }
  }
}
```
| 形 | 使う場所 | 例 |
| --- | --- | --- |
| `asset` | 資産額（プレイ中・結果・投稿文・結果画像） | 5,123.4万円、12,345.6万円 |
| `whole` | 文中の金額（「毎月10万円」「元本2,400万円」など） | 10万円 |
| `plain` | 細かい金額（今は使わない） | 4,167円 |

- `formatMoney(amount, kind)` ＝ `prefix ＋（amount ÷ divisor を decimals 桁で四捨五入、grouping なら3桁区切り）＋ suffix`
- 例：ドルを足すなら `asset` を `{ "divisor": 1000, "decimals": 1, "prefix": "$", "suffix": "K", "grouping": true }` で「$16.9K」。処理は直さない
- `core/` は通貨に依存しない（毎月受け取る額と最小単位を引数で受け取るだけ）
- 「万円」は JSON の中にあるので、T-17（`.ts` に日本語を書かない）にそのまま合う

1. `data/i18n/<言語>.json` を作る 2. 必要なら `data/currency/<通貨>.json` 3. 選び方と切り替えの場所を決める（U10） 4. フォント・色・OGP・免責を確認 5. テストを追加した言語・通貨でも回す

## 14. 守ること（まとめ）
- 決定事項（2.1）は変えない。変えたほうがよいと思ったら、理由と案を添えてオーナーに確認
- 画面に見えるもの・遊び方・文言・計測・費用に関わることは、書かれていなければ確認する。確認は1回に1つ、おすすめと理由、残りの数を添える
- `core/` は画面に依存させず、参照実装と同じ結果（T-02）。乱数の順番を変えない
- **データはコードに書かず JSON で持つ**（6.6）。文言は `data/i18n/ja.json`、初期資金と金額の表記は `data/currency/jpy.json`、期間・速さは `data/config.json`、シナリオは `data/scenarios.json`、称号の条件は `data/titles.json`
- 端末への保存は try/catch
- 実在の人物・企業・メディア・金融機関・商品・銘柄・指数の名前を使わない
- 免責を全画面に出す。「積立なら必ず勝てる」と受け取られる文を入れない
- 個人情報・相場番号・売買の内容を計測で送らない
- 設計書と実装が食い違ったまま進めない

## 15. 用語
| 用語 | 意味 |
| --- | --- |
| 積立 | 毎月受け取る10万円を、その月の終値で買い続ける比較相手（売らない） |
| 元本 | 受け取ったお金の合計。20年で2,400万円 |
| 平均の買値 | 株を買うのに使った額÷株数（買い足しを含む） |

| ローソク足（月足） | 1か月の始値・高値・安値・終値を1本の棒にした図 |
| 終値 | その月の最後の値段。売買はこの値段で成立 |
| 相場番号（シード） | 相場を作る番号。同じなら同じ相場（テスト用。画面・URLには出さない） |
| シナリオ | 相場の性格（右肩上がり・暴落と回復・乱高下・長期下落） |
| 調整 | 平常時の一時的な下落（−12〜−22%）と戻り |
| ゲームの月 | 0〜239。画面の「1年目 1月」が 0 |
